# Working on repo-brief

This repository is public. Anything committed here is published: code, tests,
fixtures, docs, `LIMITATIONS.md` rows and commit messages alike. That holds
when you work on it from a repo that vendors it, too.

- repo-brief is a generic tool. Describe a feature by what it does, never by
  whose repository it is for or where it was used.
- Nothing comes in from another repository: no names from it, no paths,
  packages, classes, methods, flags or tickets, no counts or sizes that
  describe it, none of its domain's words.
- Examples, fixtures and placeholders are JoJo's Bizarre Adventure references:
  Stands, the Joestars, the Speedwagon Foundation, `com.example.jojo`. When a
  test needs a name, take it from there, never from the repository that
  prompted the test.
- A limit found while working in another repository is written up by what went
  wrong. Leave out which repository it was and what it is built with.
